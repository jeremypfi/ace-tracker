# ACE Tracker Web Dashboard — Architecture

## Overview

A fully static multi-page website generated by Python and served via GitHub Pages (or Cloudflare Pages). No server, no database, no runtime cost. The Python script runs on a scheduled GitHub Actions cron job during hurricane season, generates all HTML pages from Jinja2 templates, and pushes them to the `gh-pages` branch for automatic deployment.

## Data Sources

### Historical (1991–last completed season)
| Source | Library | Notes |
|---|---|---|
| NOAA HURDAT2 | Tropycal | Finalized post-season best-track data. Authoritative for all completed seasons. |
| Extended Best Track (EBTRK) | RAMMB/CIRA | Adds wind radii (R34/R50/R64). Available 2004+. Required for IKE/TIKE. |

### Current Season (realtime, failover chain)
| Priority | Source | Method | Notes |
|---|---|---|---|
| 1 | Tropycal `realtime` module | Python library | Already a dependency. Reliability assessed in Phase 0B — may be demoted to Source 2 if maintenance gaps found. |
| 2 | NHC ATCF advisory feed | Direct HTTP fetch + parser | Official US government feed. Public domain. Promoted to Source 1 if Tropycal realtime is unreliable. |
| 3 | Climatlas (Dr. Ryan Maue) | HTTP fetch + parser | Previously working. Backup only. |
| 4 | Last cached copy | Read local JSON | Always succeeds. Triggers "data delayed" banner. |

The failover logic wraps each source in a try/except, logs failures, and moves to the next. The cache is always written on a successful fetch.

### Verification Sources (not in live pipeline)
| Source | Use | Notes |
|---|---|---|
| CSU Tropical (Klotzbach/CSU) | ACE/PDI spot-check | Derived from NHC — not independent, but useful for cross-checking our calculations. Terms of use unclear; contact CSU before using as a live scrape source. |
| NOAA/AOML IKE Calculator | IKE/TIKE validation | Authoritative benchmark for Phase 4 metric validation. |

## Metrics

### Phase 1 — Launch (HURDAT2 only, 1991+)
| Metric | Formula | Data Required |
|---|---|---|
| ACE | Σ(V²) × 10⁻⁴ | Max wind at 6-hr synoptic times (TS/HU/SS only) |
| PDI | Σ(V³) × 10⁻¹¹ | Same as ACE. Just a different exponent. |
| RI Events | Count of ≥30 kt increase in 24 hrs | Max wind at consecutive 6-hr intervals |
| Landfall ACE | ACE filtered to landfalling storms only | Landfall flag + timing in HURDAT2 |

### Phase 2 — Advanced (Extended Best Track, 2004+)
| Metric | Formula | Data Required |
|---|---|---|
| IKE | ∫∫ ½ρU² dA over wind field | Wind radii (R34/R50/R64) per quadrant |
| TIKE | Σ(IKE) over storm lifetime | Same as IKE |
| Hurricane Severity Index (HSI) | Size + intensity scoring | Wind radii per quadrant |

**Note:** IKE/TIKE/HSI can only be calculated from 2004 onward due to wind radii data availability in HURDAT2. Pre-2004 storms will show "N/A" for these metrics. This limitation must be clearly disclosed on the site.

## Seasonal Automation

```
May 15:   GitHub Actions cron activates (Eastern Pacific season opens)
June 1:   Atlantic cron activates
          ↓ Runs every 6 hours for both basins
November 30: Final run triggers "end of season recap" generation
             Cron deactivates until May 15
December–May: Site is static; only historical data served
```

The cron is gated by date inside the GitHub Actions workflow YAML. The Python script also checks the date independently as a second guard — if run manually in February, it skips the realtime fetch and warns loudly rather than publishing stale realtime data.

## Deployment

### GitHub Pages (recommended, free)
- Push generated HTML to `gh-pages` branch
- GitHub Pages serves automatically at `yourusername.github.io/ace-tracker` or a custom domain
- HTTPS included free via Let's Encrypt

### Custom Domain (optional, ~$12/year)
- Add a `CNAME` file to the `gh-pages` branch
- Point DNS A records to GitHub Pages IPs
- HTTPS handled automatically

### Cloudflare Pages (alternative)
- Slightly faster global CDN
- Same deployment model (static HTML push)
- Free tier sufficient

## Data Flow (per run)

```
1. Load HURDAT2 historical (Tropycal)     → storms 1991–last year
2. Load current season (failover chain)   → current year storms
3. Merge into unified storm dataset
4. Calculate ACE, PDI, RI, Landfall ACE
5. Calculate seasonal aggregates
6. Find analog seasons
7. Write cache file (for next run's fallback)
8. Render each Jinja2 template with computed data
9. Write HTML files to data/
10. GitHub Actions commits and pushes to gh-pages
```

## Reliability & Accuracy Disclosures

All pages must include:
- **"Current season data is preliminary"** — real-time values differ from NOAA's final best-track
- **"IKE/TIKE available from 2004 onward only"** — wind radii data limitation
- **Data timestamp** — when the page was last successfully updated
- **"Data delayed" banner** — shown when site is serving a cached copy due to source failures
